UKRA — Site specification

Concise site-level specification mapping the UKRA 2026–2055 blueprint to the current static prototype and the next implementation steps.

Objective

Deliver a connected, auditable public-facing site that acts as the digital operating system for the £2tn UKRA programme. Prioritise traceability (national → region → city → neighbourhood → project → contract → budget → progress → outcome).

  • Home
  • UKRA (mission, governance, technical councils, oversight)
  • 2055 Plan (Britain 2055)
  • Projects (index, map, filter, project pages)
  • Infrastructure (energy, water, transport, digital)
  • Housing (standards, design library, portal)
  • Public Services (health, police, fire, prisons, education)
  • Standards (technical libraries)
  • Procurement & Contractors
  • Finance
  • Environment
  • Jobs & Skills
  • Transparency (open data, API, audits, risk register)

Law & Planning (new top-level section)

Make construction law, planning reform and approval routes first-class parts of the site. Each reform or proposal must publish:

  • Current law / guidance
  • Problem statement and evidence
  • European comparisons
  • Proposed amendment and classification (Keep / Modify / Replace / Remove / Create)
  • Expected benefits, cost, risks and safeguards
  • Consultation documents and decision timeline

Infrastructure Capacity Certificate (feature)

Implement the blueprint's infrastructure-first idea as an interactive assessment that evaluates whether a development is infrastructure-ready across utilities, transport, schools, healthcare, green space, flood risk and biodiversity. Key outputs:

  • Per-development Infrastructure Capacity table (current vs required with traffic-light status)
  • Development status (infrastructure-ready / not infrastructure-ready)
  • List of required investments or mitigations (grid reinforcement, sewer upgrades, school places, etc.)
  • Publicly visible certificate and links to planning applications and funding actions

City portals (City 2055)

Elevate city pages into City 2055 portals with phased timelines (current, 2030, 2035, 2045, 2055), interactive maps, housing and infrastructure requirements, and project timelines. Make each portal a control panel for regional outcomes.

Data model overview

Every major object should be linked and queryable. Example primary objects:

Project {
  id,
  title,
  description,
  sector,
  region_id,
  city_id,
  neighbourhood_id,
  coordinates,
  start_date,
  expected_completion,
  status,
  capacity,
  budget_id,
  contractors[],
  documents[],
  progress[],
  risks[],
  outcomes[]
}

Budget { id, project_id, approved, committed, spent, forecast, funding_sources[] }

Contractor { id, company_name, contracts[], performance_score, safety_record }

InfrastructureCapacity { id, project_id, electricity, water, sewerage, roads, rail, fibre, schools, healthcare }

Design the site so HTML pages can be populated from the same data model (static templates + placeholder data initially, ready for dynamic wiring later).

UI components (reusable)

  • Stat cards (clickable, link to data)
  • Project progress timeline component (phase badges)
  • Standards compare matrix
  • Region/city summary panel
  • Contractor profile card
  • Document viewer (PDF/links)
  • Map with layered GIS toggles

Accessibility, content and data rules

  • High contrast, legible typography (black text by default)
  • Keyboard and screen-reader accessibility for maps and filters
  • Every statistic must link to source data or an explanation
  • Use labelled placeholders for missing live data
  • Do not invent or publish live statistics without source

API & data export

Expose non-sensitive datasets via a public API. Suggested endpoints:

GET /api/projects
GET /api/projects/:id
GET /api/regions
GET /api/finance/summary
GET /api/infrastructure-capacity/:project_id
GET /api/contractors
